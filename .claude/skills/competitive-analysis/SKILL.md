# Competitive Analysis

## Intent

Find the unserved gap by studying who else solves the same problem and how. This skill enforces the competitive + feature analysis of the Tech Fleet Market Research workshop: direct/indirect competitors → differentiation questions → comparison table → feature grid → gaps. It composes with [[market-analysis]] (the market), [[audience-segmentation]] (who), [[positioning]] (the claim), and [[product-specs]] (the what & why).

## Rules

1. **Direct vs indirect by customer overlap.** Direct = similar product **and** same target customer; indirect = different product **or** different customer, same need.
2. **Rank by product similarity, separately from the direct/indirect tag.** The most-similar *product* can still be *indirect* (right product, wrong customer). Make the two axes explicit.
3. **Design competitor questions to test YOUR differentiation.** Each question should be able to confirm or kill a claimed differentiator — not be generic.
4. **Only real, griddable products go in the table.** Non-products (do-nothing / status quo, consultants, training) are captured as **positioning notes**, not table rows.
5. **Evaluation lens: provided vs DIY.** Judge each feature on what the product provides **out of the box** (built-in, enforced, persistent), not what a user could assemble. Use **✅ full / ⚠️ partial-or-DIY (explain in-cell) / 🚫 none**.
6. **The feature grid separates table-stakes from differentiators; name the whitespace.** A capability matrix that makes the unclaimed features and the unfused combination visible.
7. **Be honest about parity and absence.** State where rivals match you (table-stakes) and where *no* head-to-head rival exists — that absence is a finding, not a blank.
8. **Keep it tight and sourced.** Short sticky notes; concise cells; a **named source** for each competitor's facts.

## Checklist before calling it done

- [ ] Direct/indirect tagged by customer overlap; similarity ranked separately
- [ ] Competitor questions each test a specific differentiator
- [ ] Only griddable products in the table; non-products → positioning notes
- [ ] Feature cells use the provided-vs-DIY lens (✅/⚠️/🚫); every ⚠️ explained
- [ ] Table-stakes vs differentiators separated; whitespace named
- [ ] Parity and "no head-to-head rival" stated honestly
- [ ] Every competitor fact grounded in a named source

## When unsure

If a "competitor" can't fill a features row (do-nothing, a consultant, a course), it's a **positioning note**, not a table row. If a feature is "possible if the user prompts or builds it," it's **⚠️ DIY**, not ✅. If the most-similar product serves a different customer, it's still **indirect** — rank ≠ tag. Hand market sizing to [[market-analysis]] and the positioning statement to [[positioning]].

## Examples

**Direct/indirect — ❌ by product only vs ✅ by customer overlap**
- ❌ "Credo AI is a governance platform like us, so it's a direct competitor."
- ✅ "Credo AI is the most-similar product but serves enterprises, not our nonprofits — rank #1 by similarity, tagged **indirect** (different customer)."

**Feature rating — ❌ binary misses DIY vs ✅ provided-vs-DIY**
- ❌ "Claude: policy generation 🚫."
- ✅ "Claude: policy generation ⚠️ DIY — can draft if prompted, not a built-in feature."
